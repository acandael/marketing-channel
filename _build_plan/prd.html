Alternative Health Practitioner Directory (Germany)

A German-language directory website that helps people find alternative health practitioners across Germany, filtered by specialty and location. To seed the directory with 300–500 quality practitioners, an admin can pre-create basic profiles and email practitioners a "claim your profile" link; once claimed, practitioners manage and enhance their profiles with premium content.

Ruby on Rails 8 Hotwire (Turbo + Stimulus) Plain CSS PostgreSQL Rails 8 built-in auth Solid Queue Active Storage Resend Cloudflare R2 Leaflet + OpenStreetMap

What the app does

  • Public directory search

    Visitors browse and filter practitioners by specialty and by city or postal code, without needing to sign up.

  • Public practitioner profile

    Each practitioner has a shareable public page with photo, bio, specialties, contact info, and a map pin.

  • Admin backend for seed profiles

    Admin logs in, creates basic (unclaimed) practitioner profiles, and manages the specialty taxonomy.

  • "Claim your profile" email flow

    Admin sends a unique claim link by email; practitioner clicks, sets a password, and takes ownership.

  • Practitioner profile management

    Claimed practitioners log in to a dashboard and edit every field on their profile via a single form.

  • Premium (enhanced) profile content

    Claimed profiles unlock richer fields — photo, long bio, gallery, opening hours, services, languages, qualifications.

Already provided by Rails 8

  • Signup, login, logout, password reset (built-in auth generator)
  • Session management
  • Database migrations
  • Background job runner (Solid Queue)
  • File uploads (Active Storage)
  • Mailer scaffolding (Action Mailer)
  • Development email previews
  • Hotwire (Turbo + Stimulus) bundled

Out of scope (v1)

  • Reviews and ratings — moderation, disputes, and fake-review handling would swamp v1.
  • Contact / inquiry form on profiles — visitors reach practitioners via the phone, email, and website already shown on the page.
  • Online booking / calendar integration — a large feature area on its own, not needed to prove the directory.
  • Payments and paid practitioner tiers — claiming and premium content are free in v1 to accelerate growth.
  • Public visitor accounts — visitors don't sign up, log in, save favourites, or bookmark.
  • Social login — only admin and claimed practitioners log in; email + password is enough.
  • Practitioner community / messaging — not the point of the site.
  • Blog and content marketing — nice for SEO later; not v1.
  • Native mobile app or browser extension — a responsive website is sufficient.
  • German UI translation — full UI stays in English for v1; German translation is a future project.
  • Rails I18n scaffolding — hard-coded English strings for v1; I18n comes with the German translation project.
  • Practitioner-facing analytics — profile view counts and click-throughs come later.
  • Bulk CSV import of practitioners — admin creates seed profiles one at a time via the admin UI in v1.
  • Radius search, map-based search, "near me" — v1 search matches by city name / postal code text only.
  • Multiple locations per practitioner — one practice address per profile.
  • Automated claim-invitation reminders — admin re-sends invitations manually.

External integrations

Resend

Transactional email

Sends "claim your profile" invitations and password-reset emails from a verified sending domain, with high deliverability.

Credentials needed

  • Resend account
  • Verified sending domain (DNS records)
  • Resend API key

Cloudflare R2

Cloud file storage

Stores profile photos and premium gallery images in the cloud so uploads survive deploys, with S3-compatible API and no bandwidth fees.

Credentials needed

  • Cloudflare account
  • R2 bucket
  • R2 API token (access key + secret)

Leaflet + OpenStreetMap

Map tiles on profiles

Renders a small map with a pin on each public practitioner profile, using OSM tiles served through Leaflet.

Credentials needed

  • None

Nominatim (OSM)

Address geocoding

Turns a German street address into latitude/longitude so it can be placed on a map and matched by location.

Credentials needed

  • None (respect usage policy: identifying User-Agent, low-volume)

Milestones

1

Foundation & Admin CRUD

Stands up the Rails project with authentication, the admin area, and the machinery for an admin to seed the directory one practitioner at a time. Nothing is public yet.

What gets built

  • New Rails 8 app with PostgreSQL, Hotwire, Solid Queue, Active Storage (local disk in dev), and Action Mailer configured for the built-in dev preview.
  • Plain-CSS styling scaffold in place (one or a few small CSS files, sensible base typography and spacing).
  • Rails 8 built-in authentication (login, logout, password reset). Users have a role of "admin" or "practitioner".
  • Rake / console task for creating the first admin user.
  • Admin area at /admin, protected by admin-role check, with a simple dashboard showing counts of practitioners by status.
  • Specialties CRUD: list, add, rename, delete (with warning when in use).
  • Practitioners CRUD covering the "basic info" fields: salutation, name, address, postal code, city, Bundesland, phone, public email, website, specialties (multi-select), published (yes/no).
  • Address geocoding on save via Nominatim; the resulting pin is previewed on a small map and manually adjustable.
  • Practitioner list with filters (status, city, specialty), name search, sort, pagination, bulk publish/unpublish and delete, per-row edit/delete/view actions.
  • Confirmation dialogs before destructive actions.

Not in this milestone

  • Any public-facing pages (homepage, search, public profile).
  • Premium fields on Practitioner (photo, bio, gallery, hours, services, etc.).
  • Claim invitation emails or Resend integration.
  • Practitioner login, dashboard, or edit form.
  • Cloudflare R2 storage (Active Storage sits on local disk until milestone 4).
  • Deployment, DNS, or production hosting concerns.

Done when: An admin can log in at /admin, create a few specialties, add a practitioner with a German address that geocodes correctly onto a preview map, see the practitioner in a filterable list, edit and delete them, and toggle published state. No public pages exist yet.

2

Public directory

Turns the admin-managed practitioner data into a public website that visitors can search and browse. Every practitioner has a real shareable URL.

What gets built

  • Public homepage that doubles as the search entry point.
  • Specialty filter (dropdown / multi-select) and location filter (text input for city name or postal code), combinable.
  • Results list of practitioner cards showing photo/placeholder, name, up to 3 specialty chips, city, tagline snippet.
  • Sensible default sort, pagination or "load more", helpful empty state.
  • Public profile page at a friendly slug URL, mobile-responsive, showing name, salutation, specialties, contact block (phone/email/website), address, and a small Leaflet + OSM map with a pin.
  • Empty premium sections render nothing (no blank blocks).
  • Subtle "Basic listing — [Name], claim your profile" ribbon on unclaimed profiles.
  • Basic SEO: title with name + city, meta description drawn from tagline, clean shareable URL.
  • Only published practitioners are visible publicly; unpublished ones return 404.

Not in this milestone

  • Radius / "near me" / map-based search.
  • Autocomplete or typo-tolerant search.
  • Reviews, ratings, contact/inquiry form, social sharing, related practitioners, structured data markup.
  • Photo, long bio, gallery, opening hours, services on the public page (premium fields don't exist yet).
  • Anything requiring practitioner login.

Done when: An anonymous visitor can open the homepage, filter by specialty and by city or postal code, see matching practitioners, click into a profile, and view name/contact/address with a working map pin. Unclaimed profiles show a subtle "Basic listing" ribbon.

3

Claim flow

Wires up transactional email so admins can invite practitioners to claim their listings, and lets a practitioner take ownership via a one-click link that leads to setting a password.

What gets built

  • Resend integration configured with API key + verified sending domain; production emails go via Resend, development emails via Rails' built-in preview.
  • "Send claim invitation" action on the admin practitioner list and edit page, with a confirm dialog pre-filling the practitioner's contact email (editable).
  • Claim invitation email (English) with friendly explanation, unique claim button, plain-text version, 30-day expiration mentioned.
  • Public claim landing page that verifies token validity, expiration, and unused status; shows a preview of the practitioner's basic info; asks the practitioner to set a password (email pre-filled and editable).
  • Successful claim creates a practitioner-role User, links it to the Practitioner, marks the invitation as claimed, sets claimed_at, logs the practitioner in, and redirects to a welcome screen or their (minimal, stub) dashboard.
  • Friendly error pages for invalid / expired / already-claimed tokens.
  • Admin sees per-practitioner invitation status ("invited on X, not claimed" / "claimed on Y") and can re-send an invitation (invalidates previous token).

Not in this milestone

  • Full practitioner dashboard or edit form (only a minimal placeholder page after claim).
  • Premium fields (photo, gallery, hours, etc.) or their editing UI.
  • Automated reminder emails.
  • Bulk claim-invitation sending.
  • Self-serve "claim this listing" from the public profile.
  • Cloudflare R2 storage setup (still on local disk).

Done when: An admin can send a claim invitation to a practitioner's email; the practitioner can open the email (in Resend or in the dev preview), click the button, set a password, and be logged in with the profile marked as claimed. Invalid/expired links show a friendly error. Admin sees claim status in the list.

4

Practitioner area & premium content

Turns the placeholder post-claim page into a real dashboard and full profile editor covering every premium field, backed by cloud storage for uploads.

What gets built

  • Login redirects practitioner-role users to their own dashboard (admin users still go to the admin area).
  • Practitioner dashboard: profile photo, name, "Edit profile" and "View my public profile" buttons, profile-completeness indicator based on premium fields.
  • Practitioner profile edit page, single form grouped into "Basic info" and "Premium content" sections with short field hints.
  • Basic info editable by practitioner (re-geocodes on address change). Specialties multi-selectable from the admin-managed list; practitioners cannot create new ones.
  • Premium fields: profile photo (upload + preview + square crop), short tagline, long bio (basic rich text: bold/italic/links/lists), services offered, opening hours (per-day fields), languages spoken, qualifications, years in practice, gallery images (multiple).
  • Publish toggle so a practitioner can hide their own listing (admin can override).
  • Settings area: change password, change login email (with re-verification), delete account (soft-delete User, profile reverts to unclaimed and admin is notified).
  • Cloudflare R2 configured as the Active Storage backend for production; local disk continues in dev.
  • Public profile page now renders premium sections when populated (and only when populated).

Not in this milestone

  • Two-factor authentication or social login.
  • Draft/published version of a profile (all saves go live).
  • Preview mode, change history, autosave.
  • Advanced image handling (filters, effects, multiple crops, gallery reorder/captions).
  • Verification badges, multiple practice locations, profile analytics.
  • German UI translation.

Done when: A claimed practitioner can log in, land on their dashboard, edit every field including uploading a photo and gallery images (stored in R2 in production), save, and see the changes reflected on their public profile page with premium sections populated. Their public listing no longer shows the "Basic listing" ribbon.
